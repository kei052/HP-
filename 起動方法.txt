履修ガチ勢：バックエンド連携版（2026年11月）

【起動手順】
1. ZIPを展開する。仮想環境 .venv は不要です。
2. 「アプリ用」フォルダーを開く。
3. 「Windowsで起動.bat」をダブルクリックするか、ターミナルで次を実行：
   python backend/app_server.py
4. ブラウザで http://127.0.0.1:8000/index.html を開く。

【重要：バックエンドのデータ連携】
- backend/database/ 内の courses.csv / jobs.csv / qualifications.csv / job_courses.csv /
  job_qualifications.csv / qualification_courses.csv が講義と適合率の参照元です。
- アプリは /api/catalog から最新のマスターデータを取得します。
- バックエンドを起動せずHTMLだけ開いた場合は、同梱時点の同じデータから生成した
  スナップショットでプレビュー表示します。その場合は編集後のCSVが反映されません。
- CSVを変更した場合はページを再読み込みしてください。
- 適合率：職業＝該当講義のscore合計/職業全score合計、資格＝関連講義の選択割合。
  履修予定を追加すると対象の職業/資格だけ黄緑の差分が表示されます。
  関連づけのない講義を追加しても黄緑は増えません（仕様通り）。
- 以前の記録は講義名で保持されます。現在のマスターと一致できない古い講義は
  適合率の計算対象になりません。登録した履修予定自体は勝手に削除されません。

【バックエンドAPI】
GET /api/catalog （アプリ用）、GET /courses、GET /jobs、GET /qualifications、
GET /courses/{id}、GET /jobs/{id}、GET /qualifications/{id}、
POST /diagnosis、POST /simulation。
POSTで使う講義IDは courses.csv の講義ID（S001など）です。
診断履歴と履修予定は既存のブラウザ保存とアカウント同期を使用します。

【アカウント同期】
- メール登録・ログインには同じ app_server.py を使用します。
- PC/スマホ同期には共通のHTTPSサーバーへの公開が必要です。
- Googleログインは GOOGLE_CLIENT_ID 等の設定が必要です。
- ローカル確認では学習用データを利用し、公開時には別途セキュリティ設定を行ってください。

【テスト】
cd backend
python -m unittest discover -s tests -v
